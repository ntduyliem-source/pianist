Pianist Web deployment bundle

This package is prepared locally; it has not been published to a domain.

1. Verify SHA256SUMS.json. The web root is site/, not the parent directory.
2. Choose a supported Caddy 2 image and pin its tested tag/digest in .env.
   Copy .env.example to .env and set PIANIST_DOMAIN to the actual DNS name.
3. Point DNS at the host and allow HTTP/HTTPS ports required for certificate
   issuance. Persist caddy_data and caddy_config when updating the container.
4. Validate: docker compose run --rm --no-deps web caddy validate
   --config /etc/caddy/Caddyfile --adapter caddyfile
5. Start: docker compose up -d
6. Run buildscripts/pianist/verify-release.py --url https://YOUR_DOMAIN/
   from the corresponding source tree. Do not disable certificate validation.
7. In Chrome/Edge, verify a fresh load, MXL -> edit -> save/reopen -> practice,
   offline install/reload and browser MIDI permission on the chosen host.

For a host with a Caddy binary instead of Docker, set PIANIST_DOMAIN and
PIANIST_WEB_ROOT, then validate/run the supplied Caddyfile.

Keep the previous release directory. For upgrades, stage the complete new
directory and switch the web root atomically. Do not replace JS/WASM files
one at a time. Existing offline tabs keep their installed release until closed.
Rollback by restoring the previous complete directory and Caddy configuration.
User projects live in that origin's IndexedDB. Export library backups before
changing the domain; browser storage is not automatically transferred.

SOURCE.json identifies the exact source archive, toolchain, Qt source and lockfile.
Host source/ and SOURCE.json alongside the downloadable release, outside any
location that would expose local development files. The source archive contains
the fork, scripts, pinned dependencies in the repository and their notices.
Keep Qt's matching source available with the corresponding binary distribution.
Qt SDK/source and npm packages are fetched by the documented build workflow;
the source archive does not contain a preinstalled SDK or node_modules.

Only the original CC0 piano example is included. The local Phố Xa test score,
browser projects, test output and user library backups are excluded.
